# Contributing

Use [GitHub Issues](https://github.com/DefinitivedCode/RepoCreator/issues) for reproducible bugs or a focused proposal before substantial changes. Include app version, platform/architecture, mode, steps, expected result and actual result. Review screenshots and logs for private information. Security vulnerabilities belong in [SECURITY.md](SECURITY.md).

For code changes, follow the [development guide](docs/development.md), preserve Windows and both Mac architectures, and keep existing product behavior. Add focused coverage for confirmed bugs and run relevant frontend, Rust and UI checks. Generated previews must continue to match files and initial commits.

Use fictional identities and generic paths in fixtures and documentation. Do not commit credentials, local settings, internal reports, build output or screenshots containing account information. Consider GitHub's [private no-reply commit email](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address) before creating commits.

Keep pull requests focused and describe the problem, resulting behavior and validation. The project uses the [MIT License](LICENSE); dependencies retain their own licenses. Release tags, visibility changes and publication are owner-controlled steps described in [release preparation](docs/releases.md).
