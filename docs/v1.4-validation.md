## Scope and remaining runtime verification

The existing CI matrix remains Windows x64, macOS Apple Silicon and macOS Intel.
Consult the pull request's checks and platform artifacts for CI results. No
physical Mac runtime or installation testing was performed locally; the
[Mac checklist](macOS-testing.md) remains applicable. Signing/notarization and
release workflows are unchanged. No tag or GitHub release was published.

Assistant launch contracts were checked against official documentation. Actual
assistant authentication/model sessions were not part of automated tests.
Antigravity IDE discovery inspects known installation locations or the configured
path without executing it. Explicit launch uses its folder arguments. Arbitrary
Windows batch files require explicit Shell mode; recognised Node package-manager
shims support structured arguments.

## Desktop refinement and discovery correction

The confirmed splash-screen cause was `get_project_tools` calling `verified_ide`,
which started Antigravity with `--help`, waited up to two seconds, then terminated
the process. Passive discovery now inspects executable locations and metadata
only. A bounded three-second cache and explicit refresh avoid repeated scans;
available, missing, invalid override and uncertain locations remain distinct.
CLI and IDE detection are independent. Windows checks include executable shims
and conventional per-user installation directories without sourcing profiles.

The rendered creation, file editors, AI configuration, review, project library,
workspace, Open, command runner, project/application settings and success views
were inspected in both themes. Default, minimum and wide layouts were exercised;
normal Simple and Advanced Overview retained their zero-scroll checks, including
display-ratio and enlarged-text cases. The technology picker now uses a bounded
dialog, sparse file pages use the existing generator's live previews, settings
use focused groups, and Open places unavailable tools in a collapsed section.
This replaces the tall catalogue, repeated context prose and disabled tool-card
grid while retaining the same creation and native execution flows.

Targeted coverage includes picker keyboard focus and multi-selection, settings
navigation, exact shared preview contents, readable extended Windows/UNC paths,
platform-specific terminal choices, passive executable markers, cache refresh,
invalid overrides and independent CLI/IDE availability. Browser tests mock the
native boundary; production WebView2 smoke checks use the compiled application.

## Appearance preferences

The header theme selector was removed. **Settings → Appearance** provides
System/Light/Dark, Slate, Muted Teal, Muted Gold, Copper, Monochrome and Custom,
a native colour input, validated hexadecimal input, live preview and reset.
Fresh installations use `#4FA69B`; older settings retain their saved theme and
migrate to Copper. Both fields use the existing preferences file and schema.

Thirty-two appearance unit cases cover validation, normalization, legacy
fallback, token application and WCAG contrast for every preset and extreme
custom colours. Foreground/button/link contrast meets 4.5:1; focus and interactive
borders meet 3:1 against supported surfaces. Status colours stay independent.
Browser coverage checks OS theme changes, explicit theme overrides, invalid
drafts leaving saved colours unchanged, preset/custom persistence, reset, header
control absence and layouts in both themes at supported sizes. Production smoke
also checks a custom accent survives an actual application restart.

Safe Git status excludes submodule contents and disables external content
filters. Filter-based projects can show conservative change results. Interactive
commands should run in the external terminal. Captured output is bounded and
ordinary child processes are owned by Job Objects/process groups; deliberately
escaping Unix process groups is outside this mechanism.

See the [workspace guide](project-workspace.md) for command trust, storage,
portability and output limits. Three separate editable identity concepts and the
README banner are available in the [branding review](branding/README.md). The
shipping icon remains unchanged.
