# v2.0.0 Beta preparation

The maintainer approved **2.0.0** on the **Beta** channel for the redesign. This page records that decision and what the version pull request does and does not cover. It does not prepare, tag, build or publish a release.

## Decision

| Item    | Value                                                                         |
| ------- | ----------------------------------------------------------------------------- |
| Version | 2.0.0                                                                         |
| Channel | Beta first, so users can exercise the redesigned workflows before Stable      |
| Reason  | First-run setup, sidebar navigation and one-page New Project change the flow  |
| Signing | Unchanged: the existing updater key and feed behaviour. No change is proposed |

## What this pull request changes

- The version in `package.json`, both fields in `package-lock.json`, `src-tauri/Cargo.toml`, the `repo-creator` entry in `src-tauri/Cargo.lock` and `src-tauri/tauri.conf.json`.
- [Release notes](release-notes/2.0.0.md) for 2.0.0, taken from the reviewed [redesign draft](release-notes/ui-redesign-draft.md). The draft stays unversioned.
- No workflow, signing, feed or updater changes.

## Not changed on purpose

- The README, `docs/README.md`, `docs/assets/README.md` and other guides still say their screenshots come from the 1.5.2 build. That is true: a fresh native capture is blocked (see the [release checklist](redesign-release-checklist.md#native-public-screenshots)). Update those mentions when new captures exist.
- Historical documents (`v1.5.1-preparation.md`, `v1.5.2-preparation.md`, `redesign-baseline.md`, `ui-redesign-brief.md`) keep their 1.5.2 references because they describe past states.

## Still required before a draft can be prepared

- This pull request reviewed and merged by the maintainer, with all four protected checks green on the exact resulting `main` commit.
- Manual checks recorded as **Not tested** in the [accessibility checklist](accessibility-checklist.md) and the [release checklist](redesign-release-checklist.md): NVDA, Narrator, VoiceOver, a physical Mac install and launch, Windows High Contrast, physical display scaling and a live signed-out GitHub check. The maintainer decides whether any must pass before publishing.
- An explicit `prepare 2.0.0 for beta release` request, which then runs the documented [release process](releases.md). Publishing stays manual.
