# v1.3 architecture audit and integration

The authoritative starting implementation was v1.2.0, commit `d00cc9f`, on a clean `main`. The audit targeted the manifests, README, frontend configuration hook/types, form panels and AI Studio, Rust configuration/preferences, preview generator, guarded repository pipeline, native processes/desktop operations, and representative unit/UI/native smoke tests. Existing generators and publication recovery were retained.

- **Canonical project configuration:** `Configuration` / `CreateRequest` in Rust and matching TypeScript types. Brief and preferred handoff template are additive, defaulted fields. Per-project commit identity is optional and never changes global Git configuration.
- **Presentation:** `App` owns navigation, local subsections and contextual panel visibility. `useCreator` continues to own the project configuration and creation state. Simple and Advanced edit that same state. Existing file and AI editors are reused within workspace sections; previews still invoke `generation::generate_files`.
- **Persistence and presets:** preference schema 4 migrates versions 1–3, preserving file/Git/AI configuration and selecting Advanced for existing installations. Fresh installations select Simple. `preset_commands` validates portable schema 1, including disabled AI drafts, before any import confirmation/persistence. Built-ins remain immutable; custom presets retain existing atomic persistence.
- **Handoff:** `handoff.ts` renders deterministic templates from project data and actual creation results. Prompt variables are substituted once, unknown fields/variables are rejected, and missing URLs are explicit. Custom templates/styles use bounded local storage. Drafts remain in memory. Rust handles native text/template dialogs and a separate bounded metadata-only recent-project history.
- **Native operations:** direct structured process arguments, executable discovery in absolute PATH/common installation locations, platform-specific editor/auth launch, allowlisted setup links, and bounded native window persistence. Project creation retains exclusive directory creation, path validation, exact staging, verified commits and recoverable remote failures.
- **Builds:** explicit Windows x64, macOS ARM64 and Intel jobs run meaningful checks and package test artifacts. Mac bundles use ad-hoc signatures without notarization. Actual Mac runtime behavior requires the manual guide.

Baseline TypeScript and 31 frontend tests passed. Native tests initially failed because sandbox temporary directories were outside the writable workspace; using a workspace TEMP/TMP resolved those environmental failures. Version 1.3 adds focused preset, handoff, migration, executable and local identity coverage, alongside adapted browser workspace tests and production Windows creation smoke tests. Automated checks never create remote test repositories.
